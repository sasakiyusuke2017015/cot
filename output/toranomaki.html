0. 基本理念

重要なのは「知識量」ではなく「問題解決能力」への移行。実務では検索・AI・ドキュメントを見ながら開発するため、 文法暗記よりも次のサイクルを体で覚えることを最優先にする。

エラー文を読む → 原因の仮説を立てる → 調査する → 修正する

3. 教師（メンター）の役割

この条件での教師は「講師」ではなくメンター兼コードレビュアー。知識を教えるのではなく、学習を設計・継続させる。

① 学習の道筋を作る 最重要

何をどの順番で学ぶかを設計し、迷わず進めるロードマップを示す。

② エラー解決の考え方を教える

答えを教えるのではなく「エラーを読む → 原因を予想 → どこを調べるか → 仮説を検証」を身につけさせる。

③ コードレビュー

毎回レビューするだけで成長速度が変わる。見るのは 命名 / 可読性 / 重複 / 責務の分離 / バグになりそうな箇所。

④ モチベーション管理

小さな目標を設定し、できたことを確認する。難しすぎる課題は出さない。

⑤ 「なぜ？」を問いかける

「なぜこの書き方にした？」「他の方法は？」「もし100件データがあったら？」——考えさせる質問で理解を深める。

🚫 教師がやらなくていいこと（書籍・動画・AIで代替できる）

文法を延々と講義する ／ スライドを読むだけ ／ 完成したコードを配る ／ すべて答えを教える

4. 質問のルール「30分ルール」

「分からなかったら聞いて」では質問する力が育たない。代わりにこう教える。

30分調べて、「分かったこと」「試したこと」「仮説」を持って聞く。

質問が具体的になり、調べる力・整理する力が同時に育つ。

5. 育成の3ステップ

STEP 1｜基礎理解 （1〜2週間）— コードが読める状態にする

  • 開発環境構築: VS Code / Git / ターミナル操作
  • プログラミング基礎: 変数 / 条件分岐 / 繰り返し / 関数 / 配列 / クラス
  • デバッグ方法: エラー文を読む / ログを見る

STEP 2｜小さい成果物を作る （2〜4週間）— 開発感覚をつける

初級

TODOアプリ / 電卓 / CSV集計ツール / 簡単なWeb API

中級

ログイン機能 / DB CRUD / ファイルアップロード / 外部API連携

完成度より「なぜこの設計にしたのか」を説明できることを重視する。

STEP 3｜実務形式へ移行 — チーム開発を経験する

  • Git: branch / commit / pull request / merge
  • コードレビュー: 命名 / 重複 / 責務分離 / エラー処理 / セキュリティ
仕様確認→ 設計→ 実装→ テスト→ レビュー→ リリース

6. やってはいけないこと

❌ 最初から大きなシステム

新人は全体像が見えず混乱する。小さく作って積み上げる。

❌ 「分からなかったら聞いて」

質問方法が育たない。→ 30分ルール（セクション4）を教える。

❌ 文法暗記中心

実務では検索・AI・ドキュメントを見る。知識量より問題解決能力。

7. 伸びる人・伸びにくい人

🌱 伸びる新人

  • エラーを怖がらない
  • 仮説を立てる
  • 調べた内容を整理できる
  • 質問が具体的
  • 他人のコードを読む努力をする

🥀 伸びにくい新人

  • 答えを待つ
  • 動けばOKで済ませる
  • なぜ動くか説明できない

8. 毎回まわすサイクル

ゴールを明確にする→ 学ぶ内容を整理する→ 詰まったときの考え方を示す→ レビューで改善点を伝える→ 次回までの宿題を設定する

このサイクルを回せれば、限られた時間でも着実に力が伸びる。
